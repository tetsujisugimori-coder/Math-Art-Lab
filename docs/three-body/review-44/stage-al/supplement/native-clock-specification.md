# P2-AL01 correction: process-native clocks

clock-contract.json supersedes only the Node-clock portion of AK's C/D/E specification for future implementation. Historical AK28 bytes remain unchanged. Native M is a Windows EXE, not a Node host: C/D/E use QPC/QPF elapsed candidates and GetProcessTimes CPU. P/W remain Node performance.now and process.cpuUsage; F is offline and G uses its actual owner P or M. R's actual OS/provider remains NOT_BOUND/NOT_OBTAINED. R cannot acquire a usable interval by borrowing M's counter or guest timestamps.

| Clock | Raw/source | Units and conversion | Domain/boundaries |
|---|---|---|---|
| M wall | successful QPC signed64 count + successful QPF positive signed64 frequency | counts; exact ms rational delta*1000/frequency | own M incarnation/thread/boot/VM generation/trial; named sample pair |
| M process CPU | GetProcessTimes user/kernel unsigned64 FILETIME duration counters |100ns; ms rational delta/10000 | retained process identity, scope PROCESS, sample group IDs |
| M optional thread CPU | GetThreadTimes user/kernel |100ns; separate THREAD scope | thread incarnation and local group; never substitute for PROCESS |
| P/W wall | performance.now finite nonnegative raw number |ms | same process/thread/origin, no shared-epoch claim |
| P/W CPU | process.cpuUsage user/system |us | whole process, optional thread API separate |
| R wall/CPU | provider/host not fixed |NOT_OBTAINED | only causal receipt/nonce/sequence linkage presently |

QPF is retained at initialization with boot origin and acquisition status. Frequency drift, raw signed range overflow, delta>=2^63, reverse order, unit/API/domain/boundary mismatch reject; wrap is never repaired. Raw negative QPC values are supported within signed range, while delta must be nonnegative. Rational calculations use BigInt only in the offline mock, not an implemented native clock. Future native conversion must check intermediate arithmetic via quotient/remainder or appropriate wide/multiword operations; no assumption of compiler __int128. Missing/failed wall/frequency is NOT_OBTAINED without fallback or zero fill. Missing/failed CPU leaves wall but yields PARTIAL; contradictory counters are INVALID. Process CPU may exceed wall on multicore; no clamp, fake-CPU inference or residual OS/GC/JIT allocation is allowed.

Start/end are named monitor.enrolled/monitor.exit-observed or an explicitly different terminal-failure envelope, with pair/group IDs and increasing sequence. STOP or ACK cannot masquerade as exit boundary. Include own M work, IPC/polling/stop decision and clock-read overhead between markers; exclude prestart creation, postend cleanup and other actors' CPU. QPC and CPU reads are not atomic: a sample group records read order/brackets. Identical group IDs are attribution, not proof of simultaneous measurement. GetProcessTimes creation/exit absolute FILETIME1601 values are identity/exit metadata, not CPU duration; live-process exitTime is undefined and cannot prove exit. A timeout-decision event and body begin/end remain distinct from these monitor boundaries. Causal IPC ordering is not permission to subtract M/P/W/R clocks, even if native QPC is generally system-wide.

Raw schema retains API return/error, values/units/frequency, domain tuple, sample IDs, named boundary, sequence and CPU scope. Well-typed fabricated samples cannot be authenticated by this pure validator: physical remains NOT_TESTED, and actual API/handle/raw provenance needs independent future evidence. GetThreadTimes is specified as an optional separate stream; process interval rejects THREAD scope.

Primary Microsoft references checked2026-11-17: [QPC](https://learn.microsoft.com/en-us/windows/win32/api/profileapi/nf-profileapi-queryperformancecounter), [QPF](https://learn.microsoft.com/en-us/windows/win32/api/profileapi/nf-profileapi-queryperformancefrequency), [GetProcessTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes), [GetThreadTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getthreadtimes). These source specifications are not host observations.

The calculator uses a trusted actor/interval-kind registry fixed in code and sealed clock-contract.json: M envelope or separately named monitor-failure, P request/receipt, W body begin/end. Caller-declared matching names cannot authorize a new boundary. Boundary/sample identifiers and expected event names must be nonblank strings.
