# Stage AO 証拠保全監査の独立性基準改訂（所有者判断）

- 決定日：2026-11-18 JST
- 対象：Math-Art-Lab PR #44、Stage AN 原ZIPを含む Stage AO の非機密証拠3ファイルの保全・照合
- 決定主体：リポジトリ所有者（単独開発であることを前提に、チャット上で監査基準の変更を明示）
- 性質：**今後の保全受入基準に対する所有者判断**。この文書だけでは個々のコピー・ACL・監査・実行が成功した証拠にはならない。
- 既存の Stage AN 記録・原物・先行レビューは過去時点の証拠として維持し、上書きしない。

## 変更理由

単独開発では、保全対象の原本一致を再確認するたびに別の Windows アカウント／別の人間／別PCを必須とするのは運用負荷が過大である。監査目的は、**保存先の実物が原本と一致し、ZIP 内部の全エントリ・manifest・inventory も整合すること**の技術的な再検証である。人間・OS権限分離の保証を、ファイル内容の再検証と混同しない。

## 改訂後の必須条件

1. **別 Windows アカウント、別 PC、別の人間は必須としない。** 同一 Windows ユーザーでも、A（コピー実行）と B（再検証）は別の Codex CLI セッションまたは別プロセスで実施してよい。
2. B は A の PASS 報告を結果として再利用せず、**保存先の原ファイルを新規に開いて読み戻す**。元の3ファイルおよび保存コピーは変更禁止。B の検証は読み取り専用操作に限定する。
3. B は元原物の記録済みサイズ・SHA-256と保存先の3/3全バイト照合、原ZIPの209/209 entriesの集合・サイズ・SHA-256・CRC32、ZIP内外manifestの一致、inventoryの照合を独自に実行する。Aの検査コードをそのまま信用せず、検証方法と入力を監査記録に明記する。
4. A/Bそれぞれの実行ID・セッション／PID・Windowsアカウント境界・実行日時・アクセス経路・照合方法・期待値の出典・生結果・失敗／欠測を新規ログに記録する。同じアカウントなら `AUDITOR_INDEPENDENCE=LIMITED_SAME_ACCOUNT` と明示し、権限分離や改変不能性の証明とは主張しない。
5. 保持期間、削除条件、非機密範囲、保存先の対象・実効アクセス権と原物の追跡性を別途確定する。既存ファイルの削除・移動・上書きは別承認制。承認されていない新たな転送先や権限変更を行わない。
6. **受入判定は二軸にする。** `CONTENT_INTEGRITY` は全バイト・エントリ照合の成否、`AUDITOR_INDEPENDENCE` は監査の分離範囲を表す。同一アカウントでも、所定の証拠と保存条件が揃えば `PERSISTENT_ARCHIVE` の正式受入を審査できるが、独立性が「完全」とは表記しない。未実施・不整合・欠損があれば HOLD/BLOCKED のまま。
7. この変更は **Stage AOの証拠保全監査のみ** に適用する。Windows隔離VM、外部回復機構R、Job Object／native ABI、AK01／AK02の物理安全性、IMPLEMENT_ONLY／QUALIFICATION_RUN の承認・実施条件は一切緩和しない。
