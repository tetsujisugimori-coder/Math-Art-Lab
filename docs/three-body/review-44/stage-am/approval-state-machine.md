# Approval state model, not an operational gate
See approval-transitions.json for all finite allowed edges. Each row fixes evidence, authority and refusal. Pure modelTransition returns modelState only and assurance SYNTHETIC_ONLY; gate state remains PLAN_ONLY. It has no persisted state or real trust verification and is not a future runtime approval validator.
PLAN_ONLY→SPEC_READY→REVIEW_PENDING. Independent review failure→REVIEW_FAILED; new independent pass with source binding/no open P1/P2→IMPLEMENTATION_ELIGIBLE. Eligibility is not authorization; missing approval→APPROVAL_MISSING→HOLD.
IMPLEMENTATION_ELIGIBLE→IMPLEMENT_ONLY requires an explicit owner implementation-only approval bound to exact HEAD/tree/source/plan/environment/scope, VM/generation/epoch and validity. It does not authorize running binaries, qualification, IPC auth or VM operations.
After separately version-fixed implementation: IMPLEMENT_ONLY→QUALIFICATION_BLOCKED. Independently proven recovery/atomic containment, finite plan, exact real environment and source-bound review are prerequisites to QUALIFICATION_READY. Another owner approval with OWNER_QUALIFY action is required for QUALIFICATION_RUN. No such approval is acquired.
Real approval requirements (future separate change): original signed authenticated owner bytes, pinned trusted issuer/key and independent raw acquisition/readback, exact grant descriptor/record ID/nonce/version, source/environment/scope identities, issued/expiry against trusted time, current revocation status, consumed approval ledger, permission-specific authority. An actual boolean or synthetic receipt is always rejected by the current operational gate.
The synthetic approval fixture raw includes the complete grant descriptor and must match all supplied metadata; changing target HEAD and approval HEAD together cannot reuse the raw. This tests binding, not actual cryptographic authenticity. Synthetic producer/reader labels never become external proof; gate ignores all inputs.
BLOCKED/REVIEW_FAILED and any failed model context are latched. Late STOP, VM_STOPPED, normal events cannot erase credential failure, rollback or safety breach. Any future recovery/new cohort requires preserved old failure, fresh identities/nonces and separate owner decision; no reset transition is implemented here.
Real implementation eligibility decision for this stage remains HOLD/APPROVAL_MISSING, implementation NO. Proposed clock/stop deadlines must fit inherited ceilings and be independently measured before finite qualification; model states do not provide that evidence.
