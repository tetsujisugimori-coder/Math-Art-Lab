# Windows Chromium 本番・累積セッション診断

初回35/36、コントラスト修正後35/36、Chromium trace付き連続実行17/18で、最後の性能試験が30秒の全体制限に達しました。単独trace付き2/2は成功。制限時間は変更していません。

保存した`production-performance-trace.zip`の`test.trace`・`0-trace.trace`より：

- 計測開始のPlaywright API時刻44,453.074ms、計測evaluate完了49,544.392ms。
- 一時停止clickの要求50,275.921ms、最初のlocatorログ66,057.873ms。要求からそのログまで約15.782秒。
- 実際のclick actionログ74,432.352ms、click完了74,454.616ms。停止後のdata-playing=falseとCanvasの確定ステップ一致は確認されたが、テスト全体は既にtimeout。
- 採取された20標本では計算CPU最大3ms、描画命令投入CPU最大2.4ms。標本の短さと、操作要求の長い待ちを区別する必要がある。
- 連続実行では前のテスト群が同一workerブラウザーで多数の全ページ画像を撮影していた。ただし、これを遅延の根本原因と断定しない。GPU・ブラウザープロトコル・Windows資源競合の内訳は未確定。

計測試験は独立した新しいブラウザープロセスで行うよう変更。これは測定条件を隔離する変更で、製品の物理モデルやtimeoutを変更していない。従来の通常操作試験は共有ブラウザーで継続する。新条件の成功をもって、元の累積ブラウザー状態における遅延を解消したとは報告しない。長いブラウザーセッションの操作応答は独立レビュー・実機測定で追加確認が必要。
