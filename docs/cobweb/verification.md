# Cobweb Model 検証記録

2026-11-05 / Windows / Node.js 24.20.0 / Chromium・WebKit / Playwright 1.58系。

## 途中で検出した失敗

1. PowerShellの実行ポリシーで `npm.ps1` を起動できなかった。ポリシーを変更せず `npm.cmd` を使用した。
2. 制限環境ではesbuildが親ディレクトリを参照できず、Vitestの設定読込に失敗した。許可された実行環境で同じ標準コマンドを実行し、289単体テストと型検査・ビルドに成功した。テスト・製品コードの修正で回避したものではない。
3. 開発E2Eの初回は既存4173番サーバーを再利用し、別作業フォルダの第12作までしかない旧版を参照した。Chromiumの最初の3ケースが選択肢待ちでタイムアウトし、中断。以後は4273番を専有して当該作業フォルダを起動。ほかの作業のサーバーは停止していない。開発／本番のポートを環境変数で指定できるようにした。明示ポート指定時は既存サーバーを再利用しない。
4. 最初の正しい対象への追加開発E2Eは **13成功・5失敗**。Chromium 9/9成功。WebKitは教材のEscape、ResizeObserver通知ループ、320px・200%文字時の横溢れを検出。マウス操作したWebKitのボタンはフォーカスをroot内へ移さない場合があるため、Escapeをライフサイクルで解除するdocumentイベントへ変更。ResizeObserver内の描画を次フレームへ移し、数式を横スクロール領域へ収めた。エラーを無視するフィルターや期待値の緩和は追加していない。
5. 修正後の追加開発18/18成功時点の固定HEAD `4002566` を独立レビューし、WebKitダークのネイティブselectのコントラスト不良（P2）を検出。[初回指摘と修正](review/README.md)を保存。ネイティブ描画をテーマに従う描画へ変更し、スクリーンショットの背景画素と文字のコントラスト比を測る判定を追加した。
6. `4002566` のCIは製品修正で後続HEADに置き換わったため中断した。`5865faf` の[標準CI初回](https://github.com/tetsujisugimori-coder/Math-Art-Lab/actions/runs/42009622439/attempts/1)は単体・型・ビルド成功、開発 **475成功・1失敗・2既存skip**。既存の反応拡散 `retired instance cannot affect remount; active instance error must stop` が `page.evaluate: Target page, context or browser has been closed` で失敗した。本番全回帰は前段失敗により未実行。[失敗ステップの生ログ](ci-failure.log)を保存。同じHEADの失敗ジョブを1回再実行した。
7. ローカルの長い全回帰は [427成功・5失敗・1既存skip](dev-full.log) を記録した時点で中断。既存WebKitの反応拡散凡例・波紋プリセット・フラクタルの双子3ケースで失敗した。ホストの空きメモリ **55MiB／16,088MiB** を観測したため、自分の全回帰を中断してブラウザを解放した。中断後19:52:41 JSTの観測は **2,795MiB**。メモリ逼迫を観測したことと、各失敗の原因がメモリであることは区別し、因果関係は未確定。478件の全完了・全成功とは扱わない。後続のローカル本番全回帰は開始していない。追加本番18件はこの中断前に別途全成功している。
   このローカル全回帰は4002566時点で開始し、実行中に5865fafのCSS修正と画像コントラスト判定を追加したため、固定最終HEAD全回帰の証拠ではない。影響する新作の最終18件は別途全成功し、固定HEADの標準全回帰はCIで確認する。
8. CIとローカルで最初に検出した既存3ケースを、待機上限・期待値・retry設定を変更せず各3回再実行した。元のmain `6dbeeb728162529671a58ab8889f4e8fbc3215cc` を一時領域へ展開した対照は [9/9成功](baseline-rechecks.log)、製品HEAD `5865faf` も [9/9成功](final-rechecks.log)。元のmain上で失敗が再現したわけではないため、既存不具合や環境原因と断定せず、原因は **UNKNOWN** とする。単独成功を元の全回帰失敗の取り消しに使わない。
9. 残る既存フラクタルの双子3ケースも各3回再確認し、[mainで9/9成功](baseline-twins-rechecks.log)、[5865fafで9/9成功](final-twins-rechecks.log)。既存6ケースの個別再確認は合計でmain 18/18、製品HEAD 18/18となった。これも全回帰の合格とは別の結果である。再実行コマンドの最初の起動は自動許可審査が時間切れとなり未起動だったが、許可された1回の再試行で実行できた。
10. 同じ製品HEADの[標準CI再実行（attempt 2）](https://github.com/tetsujisugimori-coder/Math-Art-Lab/actions/runs/42009622439/attempts/2)が **成功**。単体289成功、型・ビルド成功、開発 **476成功・2既存skip**（19.3分）、本番 **358成功**（10.1分）。[全ステップの生ログ](ci-attempt-2.log)を保存。最初のCI失敗・ローカル中断・原因UNKNOWNという記録は残す。PRなのでPagesへのデプロイは実行していない。
