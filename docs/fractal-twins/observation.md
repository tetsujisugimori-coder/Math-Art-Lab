# 点の足跡を観察する：設計と検証

要求原本は [Issue #20](https://github.com/tetsujisugimori-coder/Math-Art-Lab/issues/20)。既存の左右画像、4段階教材、最大16段の数列表を維持し、一方の軌道を図と直近の計算で追う観察モードを追加する。

## 操作と図の役割

「006 · フラクタルの双子」→「点の足跡を観察する」。左の画像でcを選ぶとz₀=0、右でz₀を選ぶと現在のcを固定して観察する。選択は既存のマウス・タップ・キーボード経路と検証を共有する。右の出発点には数値入力を追加した。未適用候補や範囲外選択は有効な観察を変更しない。

足跡は専用のz平面を一つ使い、現在観察する側を左右の画像と観察欄に表示する。Mandelbrotの画像はc平面であり、そこへzの軌道を重ねると座標の役割を混同するため、この方式を採用した。背景は無地の暗色と座標軸。実在しないフラクタル形状・軌道は描かない。左右の選択画像はそのまま維持し、観察ステップでWorkerへ追加の画像要求を送らない。

SVGは実計算の点を直線で接続する。出発点は□、過去は○、現在は◆。最大32点の履歴と省略数を示し、出発点は別に残す。同一点への往復でもn・数値・直近の計算を更新する。予告点、滑らかな補間、軌跡の装飾は追加していない。背景画像と足跡の表示範囲は独立し、同じ座標変換関数を使う。図の枠外と発散を別表示し、枠外の点は端へ置き換えない。線分はLiang–Barsky法で交点までクリップし、正規化座標が1e9を超えるなど不安定な幾何は描画しない。

観察開始・条件適用・例の選択はn=0で停止。「最初に戻す」はc・z₀を保持する。再生間隔は1秒、reduced-motionでは2秒で、利用者の開始操作を必要とする。選択側・条件変更、終了、タブ非表示、作品切替で停止。タイマーの世代トークンで予約済みの古いコールバックも拒否する。読み上げのstatus通知は手動操作・開始停止・終端に限定し、自動再生の各ステップでは更新しない。

観察終了は適用済み設定と表示範囲を保持する。観察中は従来の左右同時の数列表とその送り操作を隠し、通常表示へ戻ると再表示する。4段階教材との同時操作は避け、教材から観察へ移ると教材開始前の設定を復元して観察を始める。観察から教材へ移ると再生を止めて教材の先頭へフォーカスを移す。教材終了後の状態・フォーカス復帰を維持する。

## 数学と停止条件

`twins-observation.ts` はDOMと描画から独立している。既存のquadratic、escapeRadius、validateTwins、formatTwinsNumberを再利用し、基本式・入力範囲・背景計算は変更しない。

| 条件 | 手計算・独立基準 | 観察の扱い |
|---|---|---|
| M、c=−1、z₀=0 | 0→−1→0→−1 | 1操作でnを1増加。周期例は手計算で説明 |
| J、c=0、z₀=0.5 | 0.5→0.25→0.0625→0.00390625 | binary64で正確な2進分数を照合 |
| M、c=1、z₀=0 | 0→1→2→5 | R=2を厳密に超えるn=3で停止 |
| J、c=−2.8125、z₀=2.25 | 2.25²−2.8125=2.25 | R=3.8125、Nまで未観測。R=2の誤用を検出 |
| M、c=−0.75+0.1i／−0.8+0.156i／0.285+0.01i | Python complexで初回超過n=33／252／19 | 背景と観察の代表条件も照合 |

脱出半径の根拠は[既存の数学記録](README.md#発散半径と有限反復)のまま。MはR=2、JはR=max(2,|c|+1)、厳密な比較`|z|>R`。二乗絶対値による比較を背景と共有する。n=0で既に閾値を超えるJulia出発点も扱う。

N=50〜500で止め、「設定回数まで発散を確認できず」と表示する。計算上の初回超過も数値近似の観測であり、丸め誤差がない数学的証明は主張しない。個々の有限観察から一般の所属・周期・収束を断定しない。

積のアンダーフロー（非ゼロ因子の積が0になる場合）を検出したら、最後の有効なnとzを保って精度制約として停止する。たとえばc=0、z₀=1e−200の二乗を0に更新して「到達した」と見せない。これは保守的な保護で、cへの微小加算の吸収など全丸め誤差を検出するものではない。非有限値は計算不能として別扱い。表示は有効数字10桁の約値、微小非ゼロ値を保持し、−0は0に整える。

## 検証範囲

追加単体14件は既知の軌道、初期点判定、上限と32点保持、無効入力、精度停止、非有限値、範囲外と発散の区別、線分クリップ、二重再生・停止後の古いコールバックを確認する。製品コードだけを呼ぶ自己照合にせず、手計算の値とPythonの独立基準値を用いる。

追加開発E2E22件、本番6件。Chromium／Windows WebKit、320/375/390/1280px、dark/light、DPR2、200%文字、reduced-motion、キーボード、タッチ相当操作を含む。現在のダイヤ形のSVG座標を計算値から独立して照合し、背景の要求世代・実画素・最新画像確定・nの一致を検査する。単なるCanvas/SVGの存在判定ではない。再生停止、手動継続、条件変更、非表示、作品切替、教材復帰も検証する。非表示は合成visibilitychangeであり、実機OSのライフサイクル試験とは区別する。

開発中、巨大座標のクリップで交点が同一座標へ丸められる不具合を単体テストが検出し、描画安全範囲のガードを追加した。GUI画像では汎用sectionの2列指定による図の縮小、原点と出発点ラベルの重なり、WebKitネイティブselectの低コントラストを見つけ、専用レイアウト・ラベル位置・明示色で修正した。図の最小幅をE2Eへ追加した。

WebKitのクリックはボタンのフォーカスを保証しない。クリック後にフォーカスを確認せずEscapeを送った新テストは8件失敗したため、教材先頭へのフォーカス移動を実装し、Tab→Enter→Escapeの実際のキーボード経路へテストを改めた。状態復元の期待値は変更していない。

ローカルは型・単体109/109・独立Python基準・全開発174/174（22.2分）が成功。全開発後の画像確認でWebKitのネイティブselectの背景指定だけではコントラストが不足したため、appearance:noneと明示色・矢印へ調整した。その後、観察22/22（2.7分）・本番ビルド・全本番56/56（3.5分）・diff検査が成功。最終HEADに対する全件CIはPRに記録する。既存5作品の内訳は単体70、開発106、本番36で、すべて成功。
