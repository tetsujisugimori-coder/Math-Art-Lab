## 数学モデル

添字は **j=0,…,N−1**。`p_j=(R cos(2πj/N+θ), R sin(2πj/N+θ))`。重複せずN個生成する。全波源の共通振幅はA、全波源の角振動数は `ω=2π/6 rad/s`。入力θとφ₀は度、内部計算はラジアン。

`r_j=√((x−x_j)²+(y−y_j)²)`、`k=2π/λ`、`u_j=A cos(kr_j−ωt+φ_j)`、`u=Σu_j`。

`X=ΣA cos(kr_j+φ_j)`、`Y=ΣA sin(kr_j+φ_j)`。`cos(a−b)=cos(a)cos(b)+sin(a)sin(b)`より `u=X cos(ωt)+Y sin(ωt)`。`C=|ΣA exp(i(kr_j+φ_j))|=√(X²+Y²)`、`I=C²`。CとIは時間に依存せず、uだけが時間で変化する。時刻の表示値を保持し、三角関数は周期6の剰余で評価する。

基本モードは全位相0。2π/N回転すると観察点と波源の距離の集合が巡回置換されるため、和u、複素和の大きさC、Iは不変。見える花弁の本数はλ・R・窓・色変換にも依存し、Nとは同一視しない。発展モードは波源0だけφ₀を変更し、基本対称性が一般に崩れる。特別な設定で対称性が残る可能性はある。

**理想化**：距離減衰・反射・到達前線なし。波は領域全体に存在する。Iは教材用の強度相当量で、実際の照度や水面波エネルギーの厳密モデルではない。この範囲は画面・数式・教材・計算で一致させた。

## 数式と図の連携

ネイティブbuttonを数式の各項に配置し、クリック／タップ／Tabフォーカス／Enter／Spaceで選択。日本語の読み方・意味、`aria-pressed`、図の輪・線・弧・数値を連動させる。「図形を確認」で図へフォーカスし、強調解除も可能。

| 記号 | 図・説明 |
|---|---|
| N、Σ | 全波源の輪。j=0〜N−1、シグマは指定範囲の全部を足す |
| R | 中心から全波源への実線 |
| λ、k | 波源0の同心円の半径差と線分がλ、k=2π/λ。円は距離のガイドで到達前線ではない |
| θ | 右向き0°からの回転弧と矢印 |
| r_j | 選択した波源jとPを結ぶ破線、距離数値 |
| A_j | 対象波源の共通振幅Aに比例する縦線と数値 |
| φ_j | t=0の基準r=λの山と、φ₀を反映したr=λ(1−φ₀/360)の山。波源0を対象と明記 |
| C、I、u、t、ω | Pの十字とCに比例する円、Pのu／C／I数値、時刻と周期の説明 |

基本モードの破線は円周配置の鏡映軸。位相を崩したモードでは配置の軸であり、干渉模様の対称性を示す保証はないと説明する。円形の表示窓では補助円の一部が切れる。

## 描画と色尺度

Canvas 2D。384×384固定、DPR・CSS表示サイズに依存させない。モデル座標は正方形[−5,5]²の画素中心、半径4.85の円形窓で切り取る。窓の外は背景色で、追加の波や減衰を導入しない。SVGは別層で位置・距離等を描く。

設定変更時だけX/Y/CのFloat64Arrayを事前計算し、uは時刻のsin/cosの線形結合で描く。モード・色彩・P・演出・画面サイズの変更では波源の三角関数を再計算しない。色変換は2049段のLUT、最大量子化差は今回の画素照合で1/255以下。C/Iは時間だけで再描画しない。表示上限30回/秒、ブラウザが遅い場合にそのFPSを保証しない。

Nごとの固定尺度で **u/(2N)、C/(2N)、I/(4N²)**。Aで割らず、Aの増減を色・数値に残す。変位は青=負／暗=0／金=正、明度曲線|q|^0.65。Cはq^0.7、Iはq^0.4でパレット補間。各モードの上限・変換・符号を凡例に表示する。光彩は同じ計算画像を96²の別Canvasへ、1pxずつずらして9回加算（globalAlpha=0.18）、CSS opacity=0.3で重ねる。画面サイズのCSS blur・mix-blend-modeは使わない。基礎ラスタ・数値を変更しないが合成後の色は重なるので、定量比較は光彩OFFと明記する。

主要配列の上限はX/Y/C合計3,538,944 bytes、ImageData 589,824 bytes、384²＋96²のCanvasのRGBA合計626,688 bytes（ブラウザ内部・GPU・合成の総メモリではない）。高DPRでもこれらは増えない。拡大時の画素近似は残る。

## 失敗と修正履歴

1. 環境：サンドボックス内でesbuildの親ディレクトリ参照を拒否。許可された昇格実行で起動。専用設定をtoolsに置いた初回はcwdがtoolsになりViteが見つからなかった。webServer.cwdをリポジトリルートへ明示（[起動失敗](e2e-development-initial.txt)）。
2. 初回開発：21/22成功、WebKitの教材Escapeが失敗。クリックでbodyへフォーカスが残る場合、rootのbubble listenerにキーが届かなかった。documentのcapture listenerへ変更し、dispose時にはAbortControllerで解除（[初回ログ](e2e-development-first.txt)）。
3. 教材の観察点エラーを退避していなかった。未適用候補5.1→教材中に有効なP→終了、で両ブラウザともエラー文が消える2/2 REDを取得（[修正前](point-error-red.txt)）。候補とエラー文を一緒に退避／復元した。
4. Python基準をNode fs経由で読む初版はVitestを通ったが、tscでnode:fsの型がなく失敗した。JSON importとresolveJsonModuleへ変更し、ビルドでも基準を型検査する。
5. 初回測定の遅い画面更新を受け、毎フレームの全UI／SVG／凡例再生成を、時刻・P数値の更新に限定。初回の遅い値は[生データ](performance-initial.json)に保持し、改善を保証する説明には使わない。
6. 実画像で初期A=1では固定尺度の上半分の色が使われず暗かったため、A=1.8を初期値に選定。数学モデルや色尺度は変更していない。λガイドは中心へ向かう線分で示し、大きなλでも長さが読みやすい位置へ修正した。
7. 追加のマウス検査で円形stageの左上(100,100)を指定し、実際には円の外に当たって両browserで30秒失敗。これはテスト座標の誤りで、クリックをstage中央へ変更した。図の中央がP≈(0,0)になる期待値は保つ（[誤座標のログ](e2e-development-26.txt)）。
8. さらにPlaywrightの既定clickは、stageがviewportより大きいと「見えている部分の中央」を選ぶため、Pのyが約0.88になった。要素全体の中央座標を明示し、期待値の許容差0.05は変更しない（[開発](e2e-development-verified.txt)・[本番](e2e-production-26.txt)）。
9. 時刻更新だけの最適化後もCSS光彩ONのrAF間隔平均はChromium86.53ms／WebKit149.84ms、OFFは19.27／77.28msだった（[変更前の生データ](performance-css-glow.json)）。モデルを変えず、光彩だけを96²の9回加算へ変更。独立の基礎画素照合・光彩OFFとの不変性・DPR上限・描画障害復帰を両環境で再検証した。低速だった変更前の値も残す。
10. 最終のWebKit実画像でライトテーマの作品pickerが白地・薄色文字となることを確認。native selectの外観に依存していたため、新作の表示中だけbody classでappearanceと配色を明示し、disposeで解除。両browserの2REDを保存（[修正前](picker-red.txt)）。既存作品のpickerスタイルは変更しない。
