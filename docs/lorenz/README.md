# カオスの蝶：確認条件

初期仕様は [Issue #16](https://github.com/tetsujisugimori-coder/Math-Art-Lab/issues/16)。Issue本文は変更せず、実装判断と検証結果はLOG・PRで追跡する。

## 数値計算の確認

- `tools/lorenz-reference.py` はPython標準ライブラリのFractionで、標準条件からh=1/200の古典RK4を独立した有理数演算で計算する。1ステップ後は `(1.0031933311430772, 1.129839801362649, 0.9920510551862709)`。これはRK4自体の基準で、連続方程式の厳密解ではない。
- x=y=0ならz(t)=exp(−βt)。この解析解に対するt=1の誤差と、刻み半減で約16倍の改善を単体テストで確認する。
- 標準初期値からt=1までの刻み細分化：h=.005対.0025の3次元距離は `2.428950790343031e-6`、h=.0025対.00125は `1.5881468549577816e-7`（比約15.29）。これは短時間での自己収束の観察で、真の解への厳密な誤差上限でも、長時間の精度保証でもない。
- 再現性は同一条件・同一手法のバッファ比較、フレーム独立性は60Hz／144Hz／不均一フレーム列の同じtでの位置比較で確認する。初期値差の単調増加や長時間解の無条件一致はテストしない。

## 性能の実測

Windows上のPlaywright Chromium 145／WebKit（Safari 26.0相当のUA）。軌道計算のみ、各7回、2026-10-25 JST。ウォームアップやJITを含む観察で、端末一般の性能保証ではない。

| 計算対象 | Chromium | Windows WebKit |
| --- | --- | --- |
| 標準12,000点・1本 | 1.4〜5.6ms | 2〜12ms |
| 上限24,000点・2本 | 4.7〜5.8ms | 11〜12ms |

Float64の数値バッファは上限2本で1,152,000 bytes。描画用のFloat32位置・色とBの破線距離に加えGPUコピー・フレームバッファが必要。GPU使用量や全体メモリの実測値ではない。描画負荷はDPR・各辺の解像度と点数上限で制限する。曲線の太い管やポストプロセスは追加していない。

実機iPhone Safari、スクリーンリーダー、低性能端末、GPU負荷・電池消費・発熱・長時間利用は未検証。初期読込・FPS・GPU負荷の変更前後比較は未測定。WebKitのエミュレーションは実機Safari試験を代替しない。OS起因の実行途中WebGLコンテキスト喪失後の自動復旧は対象外。線の1px幅はGPU実装に依存し、有限画素で微細な層を分離できるとは限らない。
